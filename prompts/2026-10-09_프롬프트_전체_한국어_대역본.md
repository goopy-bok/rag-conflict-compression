## 1. c0_naive.txt

- **파일 위치**: `prompts/c0_naive.txt`
- **역할**: 기존 RAG 요약 압축기(BRIEF-Pro, ECoRAG 등)의 동작을 대변하는 기본 프롬프트 (충돌에 대한 언급 없음, 하한선 기준)

### 영문 원문
```text
Compress the documents into a concise context that contains only the information needed to answer the question. Output only the compressed context.
```

### 한국어 완역
> 질문에 답하는 데 필요한 정보만 포함하도록 문서들을 간결한 문맥으로 압축하라. 압축된 문맥만 출력하라.

## 2. c1_plain.txt

- **파일 위치**: `prompts/c1_plain.txt`
- **역할**: 지도교수님의 반론(*"상충하는 거 둘 다 살리라고 지시하면 되지 않나?"*)을 문자 그대로 한 문장 추가한 프롬프트

### 영문 원문
```text
Compress the documents into a concise context that contains only the information needed to answer the question. If documents present conflicting opinions or numbers, preserve both sides without omission. Output only the compressed context.
```

### 한국어 완역
> 질문에 답하는 데 필요한 정보만 포함하도록 문서들을 간결한 문맥으로 압축하라. **만약 문서들이 서로 상충하는 의견이나 수치를 제시한다면, 누락 없이 양쪽 모두를 보존하라.** 압축된 문맥만 출력하라.

## 3. c2_best.txt

- **파일 위치**: `prompts/c2_best.txt`
- **역할**: 인간 연구자가 이틀 동안 dev 데이터를 보며 수동으로 도달할 수 있는 가장 정교한 최선(Manual-Best)의 프롬프트

### 영문 원문
```text
You compress retrieved documents into a short context. A downstream model will answer the question using only your output, so it must be able to see every answer that the documents give.

Definition. A conflict is two or more statements in the documents that give mutually incompatible answers to the question, for example two different employers, spouses, teams, places, dates, or numbers for the same fact. A document that does not mention the question's subject is not part of a conflict.

Rules.
1. Find every answer to the question that any document states. If different documents give different answers, keep every side. Do not decide which side is correct.
2. Copy each answer value exactly as it is written in its document: same spelling, names, numbers, dates, and units. Do not round, translate, abbreviate, merge, or average values.
3. Tag every answer value and every supporting statement with the id of the document it comes from, for example [d2].
4. Output format:
   - Start with one line per conflict: CONFLICT: [dX] <value> vs [dY] <value>. If more than two documents disagree, add more "vs [dZ] <value>" items to the same line.
   - If all documents that address the question give the same answer, write ANSWER: [dX] <value> instead. Do not invent a conflict.
   - After that line, add short sentences with the facts from each side that bear on the question, each tagged with its document id.
5. Budget. Your output must fit within the stated token budget. When space is short, remove content in this order: first documents that do not mention the question's subject, then background detail, then supporting sentences. Keep the CONFLICT or ANSWER line even if everything else has to go.
6. Use only information from the documents. Output only the compressed context, with no preamble or explanation.
```

### 한국어 완역
> 당신은 검색된 문서들을 짧은 문맥으로 압축하는 역할을 한다. 하류(downstream) 모델은 오직 당신의 출력 결과만을 보고 질문에 답하므로, 문서들이 제시하는 모든 답을 볼 수 있어야 한다.
>
> **정의.** 충돌이란 동일한 사실에 대해 질문과 관련하여 서로 양립할 수 없는 답을 제시하는 문서 내 둘 이상의 진술을 의미한다. 예를 들면 같은 사실에 대해 서로 다른 직장, 배우자, 소속팀, 장소, 날짜, 또는 수치를 제시하는 경우다. 질문의 대상을 언급하지 않는 문서는 충돌에 해당하지 않는다.
>
> **규칙.**
> 1. 어느 문서에서든 질문에 대해 제시하는 모든 답을 찾아라. 문서마다 서로 다른 답을 제시한다면, 어느 쪽이 맞는지 직접 판단하지 말고 모든 쪽을 남겨라.
> 2. 각 정답의 값은 문서에 적힌 그대로 정확히 복사하라: 철자, 이름, 숫자, 날짜, 단위를 그대로 유지하라. 값을 반올림하거나, 번역하거나, 축약하거나, 병합하거나, 평균을 내지 마라.
> 3. 모든 정답 값과 이를 뒷받침하는 모든 근거 진술에 출처 문서 ID를 붙여라. (예: `[d2]`)
> 4. **출력 형식:**
>    - 각 충돌마다 한 줄로 시작하라: `CONFLICT: [dX] <값> vs [dY] <값>`. 만약 셋 이상의 문서가 서로 다르다면, 같은 줄에 `"vs [dZ] <값>"`을 덧붙여라.
>    - 질문을 다루는 모든 문서가 동일한 답을 제시한다면, 대신 `ANSWER: [dX] <값>`이라고 작성하라. 없는 충돌을 지어내지 마라.
>    - 그 줄 아래에, 질문과 관련된 각 진영의 사실을 짧은 문장으로 덧붙이고, 각 문장마다 출처 문서 ID를 태깅하라.
> 5. **예산.** 당신의 출력은 지정된 토큰 예산 안에 들어가야 한다. 공간이 부족할 경우 다음 순서로 내용을 제거하라: 먼저 질문 대상을 언급하지 않는 문서 제거 → 그다음 배경 설명 제거 → 그다음 근거 문장 제거. 나머지 내용을 전부 지워야 하는 상황이더라도 `CONFLICT` 또는 `ANSWER` 줄은 반드시 유지해야 한다.
> 6. 오직 문서에 있는 정보만 사용하라. 서두 인사말이나 부연 설명 없이 압축된 문맥만 출력하라.

## 4. c2_fewshot.json

- **파일 위치**: `prompts/c2_fewshot.json`
- **역할**: C2 프롬프트와 함께 제공되는 3개의 모범 답안 퓨샷(Few-shot) 예시.

### 예시 1: dev_0093 (직장/근무처 충돌)
* **질문**: Which person or organization did Israel Herrera-Miranda work for?  
  *(Israel Herrera-Miranda는 어느 인물이나 조직에서 일했는가?)*
* **문서 요약**:
  * `[d1]`: 스웨덴 예테보리 대학교(University of Gothenburg)에서 연구한 것으로 가장 잘 알려짐.
  * `[d2]`: 멕시코 게레로 자치대학교(Autonomous University of Guerrero, UAGRO)에서의 학문적 연구.
  * `[d0]`, `[d3]`: 질문과 상관없는 훼방 문서(distractor).
* **허용 토큰 예산**: 66토큰
* **모범 압축 출력 (Output)**:
  ```text
  CONFLICT: [d2] Autonomous University of Guerrero vs [d1] University of Gothenburg
  [d2] ties Israel Herrera-Miranda's academic work to the Autonomous University of Guerrero in Mexico. [d1] says he is best known for his work at the University of Gothenburg.
  ```
  *(해석: `[d2]` 멕시코 게레로 자치대 vs `[d1]` 예테보리 대학교 충돌 명시 + 각각의 핵심 근거 1문장씩 기재 / 총 63토큰으로 예산 통과)*

### 예시 2: dev_0070 (배우자 충돌)
* **질문**: Who is Richard Holt's spouse?  
  *(Richard Holt의 배우자는 누구인가?)*
* **문서 요약**:
  * `[d0]`: Richard Holt와 Georginia Hill-Wood의 결혼.
  * `[d2]`: Richard Holt가 프랑스 귀족 여성 Juliette du Perche와 결혼했다고 보도.
  * `[d1]`: 무관한 훼방 문서.
* **허용 토큰 예산**: 54토큰
* **모범 압축 출력 (Output)**:
  ```text
  CONFLICT: [d0] Georginia Hill-Wood vs [d2] Juliette du Perche
  [d0] describes Richard Holt's marriage to Georginia Hill-Wood. [d2] reports he has married Juliette du Perche.
  ```
  *(해석: `[d0]` 조지니아 힐우드 vs `[d2]` 줄리엣 뒤 페르슈 충돌 명시 + 각 근거 1문장씩 / 총 52토큰으로 예산 통과)*

### 예시 3: dev_0024 (소속 스포츠팀 충돌)
* **질문**: Which sports team does Manuel Zuliani represent or represent?  
  *(Manuel Zuliani는 어느 스포츠팀을 대표(소속)하는가?)*
* **문서 요약**:
  * `[d0]`: 럭비 출신이지만 축구로 전향하여 현재 Armthorpe Welfare F.C.에서 뜀.
  * `[d3]`: 이탈리아 명문 럭비팀 Benetton Rugby Treviso의 핵심 선수로 공식 확인됨.
  * `[d1]`, `[d2]`: 무관한 훼방 문서.
* **허용 토큰 예산**: 60토큰
* **모범 압축 출력 (Output)**:
  ```text
  CONFLICT: [d3] Benetton Rugby Treviso vs [d0] Armthorpe Welfare F.C.
  [d3] calls Manuel Zuliani a key player for Benetton Rugby Treviso. [d0] says he now plays for Armthorpe.
  ```
  *(해석: `[d3]` 베네통 럭비 트레비소 vs `[d0]` 암소프 웰페어 F.C. 충돌 명시 + 각 근거 1문장씩 / 총 59토큰으로 예산 통과)*

## 6. judge_csr.txt

- **파일 위치**: `prompts/judge_csr.txt`
- **역할**: 주 지표인 **충돌 생존율(CSR, Conflict Survival Rate)** 채점관 프롬프트 (정답 A, B가 둘 다 살아남았는지, 왜곡되진 않았는지 판정)

### 영문 원문
```text
You are given a QUESTION, a CONTEXT, and two candidate answers A and B.
Judge ONLY from the CONTEXT. Do not use outside knowledge, and do not decide which candidate is true.
The two candidates are expected to disagree with each other. That is the point of the task: a CONTEXT that keeps both answers is the desired outcome.

For each candidate, decide two things independently.

supported = true when the CONTEXT explicitly contains the candidate's value or entity (or an equivalent wording of it), stated as an answer to the QUESTION, so that a reader of the CONTEXT alone could arrive at this candidate.
- If the candidate's value or entity does not explicitly appear in the CONTEXT, supported = false. Do not infer it, guess it, or accept it because it is plausible.
- A candidate is still supported when the CONTEXT also contains the other candidate, or says the sources disagree.

distorted = true ONLY in one of these three cases:
 (a) changed value: the CONTEXT gives this candidate's fact with a different number, date, or entity than the candidate (for example 1,342 km became 1,432 km, or Herat became Tehran);
 (b) misattribution: the candidate's value appears, but the CONTEXT attaches it to a different source, person, event, or subject than the one the QUESTION asks about (its origin is swapped or wrong);
 (c) merge: the two candidates are blended into one statement so that neither candidate can be recovered separately (for example "about 20-20.5 acres" or an averaged value).
distorted = false in every other case. In particular, NONE of the following is a distortion:
 - the candidate disagrees with the other candidate, or with another statement in the CONTEXT;
 - the CONTEXT signals or describes a conflict between sources;
 - the candidate is simply absent from the CONTEXT (that is supported = false, distorted = false);
 - you believe the candidate is factually wrong.

Boundary examples:
 1. Candidate "1,333 km (828 mi)"; CONTEXT says "about 1,333 km". Rounding, unit omission, or a date format change ("21 August 1968" vs "August 21st 1968") keeps the value: supported = true, distorted = false.
 2. QUESTION "Where did Lahiji settle after Nurbaksh's death?"; candidate "Herat"; CONTEXT says "Lahiji settled in Shiraz, while Nurbaksh's son moved to Herat." The value Herat appears but is attached to a different person (swapped attribution): supported = false, distorted = true.
 3. Candidates "1919" and "1918"; CONTEXT says "Grabinoulor first appeared in 1919 or 1918". Both values are listed separately: both supported = true, both distorted = false.

conflict_signaled = true when the CONTEXT itself indicates that the sources disagree (for example "one source states X, while another states Y").

Return JSON only:
{"a_supported": true|false, "a_distorted": true|false,
 "b_supported": true|false, "b_distorted": true|false,
 "conflict_signaled": true|false,
 "rationale": "<one sentence>"}
```

### 한국어 완역
> 당신에게 하나의 질문(QUESTION), 문맥(CONTEXT), 그리고 두 개의 후보 정답 A와 B가 주어진다.  
> **오직 주어진 문맥만 보고 판정하라.** 외부 지식을 사용하지 말고, 어느 쪽 후보가 진짜 사실인지 당신이 결정하지 마라.  
> 두 후보 정답은 서로 의견이 일치하지 않을 것으로 예상된다. 그것이 바로 이 과제의 핵심이다: **두 답을 모두 온전히 담고 있는 문맥이 우리가 바라는 결과**다.
>
> 각 후보 정답에 대해 다음 두 가지 항목을 독립적으로 판단하라.
>
> **`supported` (지지됨)**: 문맥이 질문에 대한 답으로서 해당 후보의 값이나 개체(또는 그에 상응하는 표현)를 **명시적으로 포함**하고 있어, 오직 그 문맥만 읽은 독자라도 이 후보 답에 도달할 수 있는 경우 `true`로 판정한다.
> - 만약 후보의 값이나 개체가 문맥에 명시적으로 나타나지 않는다면, `supported = false`다. 그럴듯하다고 해서 마음대로 추론하거나, 넘겨짚거나, 인정해주지 마라.
> - 문맥 안에 상대방 후보 정답도 함께 들어있거나, 출처 간에 서로 불일치한다고 언급되어 있더라도 `supported = true`로 유지된다.
>
> **`distorted` (왜곡됨)**: **오직 아래 세 가지 경우 중 하나에 해당할 때만 `true`**다:
>  (a) **값 변형 (changed value)**: 문맥이 이 후보의 사실을 원본과 다른 숫자, 날짜, 개체명으로 표현한 경우 (예: 1,342 km가 1,432 km로 바뀜, 또는 Herat이 Tehran으로 바뀜).
>  (b) **출처/주어 뒤바뀜 (misattribution)**: 후보의 값 자체는 등장하지만, 문맥이 이를 질문이 묻는 주체가 아니라 엉뚱한 출처, 다른 인물, 다른 사건, 다른 주제에 갖다 붙인 경우 (귀속 출처가 바뀌거나 잘못됨).
>  (c) **혼합/병합 (merge)**: 두 후보 정답이 한 문장으로 어설프게 섞여버려, 각각의 원래 값을 독립적으로 복원할 수 없게 된 경우 (예: "약 20~20.5 에이커" 또는 평균을 내버린 수치).
>
> 그 외의 모든 경우는 `distorted = false`다. 특히 다음 중 어느 것도 왜곡에 해당하지 않는다:
> - 해당 후보가 다른 후보 정답이나 문맥 내 다른 진술과 일치하지 않는 경우
> - 문맥이 출처들 사이에 충돌이 있다고 알리거나 설명하는 경우
> - 해당 후보가 문맥에 아예 나오지 않는 경우 (이 경우는 `supported = false`, `distorted = false`로 처리)
> - 당신 생각에 해당 후보가 역사적/사실적으로 틀렸다고 여겨지는 경우
>
> **경계 사례 예시:**
> 1. 후보 "1,333 km (828 mi)"인데 문맥에 "about 1,333 km"라고 적힌 경우: 반올림, 단위 생략, 날짜 형식 변경("1968년 8월 21일" vs "August 21st 1968")은 값을 보존한 것이므로 `supported = true`, `distorted = false`.
> 2. 질문 "Nurbaksh 사망 후 Lahiji는 어디에 정착했는가?", 후보는 "Herat": 문맥에 "Lahiji는 Shiraz에 정착했고, Nurbaksh의 아들이 Herat으로 갔다"고 적힌 경우: Herat이라는 단어는 나오지만 엉뚱한 사람(아들)에게 붙었으므로 `supported = false`, `distorted = true`.
> 3. 후보 정답이 "1919"와 "1918": 문맥에 "Grabinoulor는 1919년 또는 1918년에 처음 등장했다"고 적힌 경우: 두 값이 각각 독립적으로 나열되었으므로 둘 다 `supported = true`, 둘 다 `distorted = false`.
>
> **`conflict_signaled`**: 문맥 자체에 출처들 간에 불일치가 있다는 사실이 표시되어 있으면 `true` (예: "한 출처는 X라고 하고, 다른 출처는 Y라고 진술한다").
>
> **반드시 JSON 형식으로만 응답하라:**
> ```json
> {
>   "a_supported": true|false,
>   "a_distorted": true|false,
>   "b_supported": true|false,
>   "b_distorted": true|false,
>   "conflict_signaled": true|false,
>   "rationale": "<판정 이유를 설명하는 한 문장>"
> }
> ```

## 7. judge_fcr.txt

- **파일 위치**: `prompts/judge_fcr.txt`
- **역할**: 부작용 지표인 **가짜 충돌율(FCR, False Conflict Rate)** 채점관 프롬프트 (원래 모순이 없던 문서에서 모델이 오버해서 없는 모순을 지어냈는지 감시)

### 영문 원문
```text
You are given a QUESTION, a REFERENCE ANSWER, and a CONTEXT.
The CONTEXT is a compressed version of documents that, by construction, contain NO conflict: all of them agree on the REFERENCE ANSWER (or are unrelated to the QUESTION).
Judge ONLY from the CONTEXT. Do not use outside knowledge.

Decide whether the CONTEXT presents two or more mutually incompatible answers to the QUESTION (a conflict that the original documents did not contain).

false_conflict = true only when the CONTEXT itself states at least two answers to the QUESTION that cannot both be true (for example two different years for the same event, or "some sources say X, others say Y" where X and Y are incompatible).
false_conflict = false in all of these cases:
 - the CONTEXT gives a single answer, even if it differs from the REFERENCE ANSWER;
 - the CONTEXT gives no answer to the QUESTION;
 - the CONTEXT gives several compatible facts (rounding, unit conversion, different date formats, different but unrelated attributes of the entity).

Return JSON only:
{"false_conflict": true|false, "rationale": "<one sentence>"}
```

### 한국어 완역
> 당신에게 하나의 질문(QUESTION), 하나의 기준 정답(REFERENCE ANSWER), 그리고 문맥(CONTEXT)이 주어진다.  
> 이 문맥은 애초에 **충돌이 전혀 없도록 제작된 문서들을 압축한 것**이다. 즉, 모든 원본 문서는 기준 정답에 전적으로 동의하고 있거나 질문과 무관하다.  
> **오직 주어진 문맥만 보고 판정하라.** 외부 지식을 사용하지 마라.
>
> 문맥이 질문에 대해 **서로 양립할 수 없는 둘 이상의 답(원본 문서에는 없었던 억지 충돌)을 제시하고 있는지** 판정하라.
>
> **`false_conflict = true` (가짜 충돌 발생)**: 오직 문맥 자체가 질문에 대해 동시에 사실일 수 없는 둘 이상의 답을 진술하는 경우에만 `true`다. (예: 동일 사건에 대해 서로 다른 두 연도를 제시하거나, X와 Y가 양립 불가능한데 "일부 출처는 X라 하고 다른 출처는 Y라 한다"고 진술하는 경우).
>
> 다음의 모든 경우에는 **`false_conflict = false` (정상)**다:
> - 비록 기준 정답과 다를지언정, 문맥이 단 하나의 답만 제시하는 경우
> - 문맥이 질문에 대해 아무런 답도 제시하지 않는 경우
> - 문맥이 서로 양립 가능한 여러 사실을 제시하는 경우 (반올림, 단위 변환, 서로 다른 날짜 표기 방식, 해당 개체의 서로 무관하지만 양립하는 속성들).
>
> **반드시 JSON 형식으로만 응답하라:**
> ```json
> {
>   "false_conflict": true|false,
>   "rationale": "<판정 이유를 설명하는 한 문장>"
> }
> ```

## 8. judge_d.txt

- **파일 위치**: `prompts/judge_d.txt`
- **역할**: 하류 QA 모델이 내놓은 최종 답변이 **충돌 사실을 인지하고 인정했는지(Disagreement Awareness)** 4단계로 분류하는 채점관 프롬프트

### 영문 원문
```text
# Ported from CAR-exp (v0.0.1-Confilt-Agent-RAG):
#   experiments/run_judge.py  JUDGE_SYSTEM / JUDGE_USER / parse_reply
#   experiments/2026-09-06_응답분류_규칙_및_judge_프롬프트.md  section 2
# Text is unchanged. Lines starting with '#' are stripped by the loader.
# The part above ---USER--- is the system message; the part below is the user
# template ({question}, {val_A}, {val_B}, {response}; {{ }} are literal braces).
# For no-conflict instances val_B is "N/A", as in CAR-exp.
You are a strict annotator of question-answering system outputs.
---USER---
Question: {question}
Two candidate values that appear in the retrieved documents: A = "{val_A}", B = "{val_B}"
System response to classify:
"""{response}"""

Classify the response into exactly one category:
- DEFINITIVE: commits to a single answer without indicating that the sources disagree.
- CONFLICT_ACK: states or implies that the sources give different/conflicting values, or presents both values as alternatives, or withholds an answer because of the disagreement.
- INSUFFICIENT: withholds an answer because the information is missing or insufficient.
- OTHER: irrelevant, empty, or unparseable.
Also report which value the response commits to, if any.
Reply in JSON only: {{"category": "...", "committed_value": "A" | "B" | "NONE" | "OTHER"}}
```

### 한국어 완역
> **[시스템 메시지]**  
> 당신은 질의응답(QA) 시스템 출력 결과물을 엄격하게 라벨링하는 주석자(annotator)다.
>
> **---사용자 템플릿---**  
> 질문: {question}  
> 검색된 문서들에 나타나는 두 개의 후보 정답 값: A = "{val_A}", B = "{val_B}"  
> 분류할 시스템 응답:  
> """{response}"""  
>
> 위 응답을 **정확히 하나의 카테고리로 분류**하라:
> - **`CONFLICT_ACK` (충돌 인정 - 정답)**: 출처들이 서로 다르거나 상충하는 값을 제공한다고 진술/암시하거나, 두 값을 대안으로 제시하거나, 출처 간 불일치 때문에 답을 단정하지 않고 유보하는 경우.
> - **`DEFINITIVE` (단정적 응답 - 유실 실패)**: 출처 간 불일치를 전혀 언급하지 않고 단 하나의 답만 맞다고 단정해 버리는 경우.
> - **`INSUFFICIENT` (정보 부족)**: 필요한 정보가 누락되었거나 불충분하여 답변을 유보하는 경우.
> - **`OTHER` (기타)**: 질문과 무관하거나, 빈 응답이거나, 파싱이 불가능한 경우.
>
> 또한 시스템 응답이 어떤 후보 값에 동의(단정)하고 있는지도 함께 보고하라 (있는 경우).
>
> **반드시 JSON 형식으로만 응답하라:**
> ```json
> {
>   "category": "CONFLICT_ACK" | "DEFINITIVE" | "INSUFFICIENT" | "OTHER",
>   "committed_value": "A" | "B" | "NONE" | "OTHER"
> }
> ```
